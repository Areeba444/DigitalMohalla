\section{Class diagrams}\label{sec:class-diagrams}
Each member drew the classes of their own packages (design step A7); every class names the requirements it realises. Table~\ref{tab:design-components-mapped-implementation} maps these classes to the code.

\begin{figure}[p]

\drawionote{class_diagram_s1}{docs/design/05_class_model/class_diagram_s1.drawio}

\textbf{Reasoning.} The lifecycle aggregate depends only on the transition table and the ports, so it can be tested without a database; the PostgreSQL event store implements the port. Indirect trust exposes one operation to Student 2's engine. \textit{Serves:} FR-B-05, B-08, B-09, FR-T-04.

\textbf{Reasoning.} A single facade runs the pipeline and returns one result object in which trust and manipulation risk are separate attributes, never averaged. Signal checks share one interface so that the Iteration 2 signals (S2, S3, S5) are added without changing the detector. The class named \code{ReciprocalClustering} realises S1, which decision D18 redefined as partner clustering. \textit{Serves:} FR-T-01 to T-08.

\section{Sequence (b): handover and return to evidence}\label{sec:sequence-b-handover-return-evidence}
\textbf{Reasoning.} An outcome is written only after both parties have confirmed, which is what makes it ``verified'' evidence (FR-T-03); the close hook writes the outcomes and refreshes the affected trust edges in the same database transaction as \code{transaction_closed}. \textit{Owner:} S1.

\section{Deployment as designed in Part A (historical)}\label{sec:deployment-part-a-historical}
The provisional Part A deployment design (design step A13) is kept for reference. It placed the whole system on one AWS EC2 host with Docker Compose and images in GitHub Container Registry, and marked the host ``to be confirmed''. The built system runs on Render and Neon instead (Section~\ref{sec:deployment}, Figure~\ref{fig:deployment-diagram}).
