\section{Non-Functional Requirements}\label{sec:non-functional-requirements}
Numeric targets are set only where Iteration 1 can measure them; the others are set in Iteration 2, once a baseline exists.

\subsection{Reliability}\label{sec:reliability}
\begin{itemize}
\item \textbf{NFR-R-01} With N simultaneous acceptances for overlapping dates, exactly one commits, in 100\% of runs. \textit{Met}: 5 parallel acceptances, 3 rounds (TC-08).
\item \textbf{NFR-R-02} Invalid lifecycle transitions are rejected 100\% of the time. \textit{Met}: 263 of 263 invalid pairs refused in Python and by the database (TC-01).
\item \textbf{NFR-R-03} Replay reproduces stored state exactly. \textit{Met}: in Python and in SQL (\code{replay_state()}), TC-07.
\item \textbf{NFR-R-04} Engine failure routes to human review. \textit{Met}: timeout and exception both hold with \code{engine_failure} (TC-36, TC-37).
\end{itemize}

\subsection{Usability}\label{sec:usability}
\begin{itemize}
\item \textbf{NFR-U-01} Every screen with an assurance state shows its evidence, never one number. \textit{Met} on the lender and moderator screens (TC-100, TC-107).
\item \textbf{NFR-U-02, U-03} Task completion and SUS scores: measured with first-time users in Iteration 2.
\item \textbf{NFR-U-05} Interface language: English in Iteration 1; Urdu is an open question.
\end{itemize}

\subsection{Performance}\label{sec:performance}
\begin{itemize}
\item \textbf{NFR-P-03} Direct-evidence assessment P95 $\leq$1 s; $k$-hop latency reported for $k=1$ to 4. \textit{Not yet measured} for the full assessment, which will be timed in Iteration 2. Measured so far for the $k$-hop component only: P95 0.08, 0.71, 4.52 and 15.92 ms for $k=1$ to 4 on the 2,026-user synthetic tier.
\item \textbf{NFR-P-04} State transition commit P95 $\leq$500 ms. \textit{Not yet measured}; TC-61 (suite 15) runs in Iteration 2.
\end{itemize}

\subsection{Security}\label{sec:security}
\begin{itemize}
\item \textbf{NFR-S-01} Passwords stored only as salted argon2 hashes; TLS for all traffic (Render terminates HTTPS).
\item \textbf{NFR-S-02} Every transition checks and records the actor's authorisation; 100\% of unauthorised attempts rejected and logged. \textit{Met} (TC-10, audit entries for refused commands).
\item \textbf{NFR-S-03} A moderator acts only in their own community. \textit{Met} (moderation tests).
\item \textbf{NFR-S-05} Audit and event logs are append-only and tamper-evident. \textit{Met}: UPDATE and DELETE refused; an altered event is detected by \code{verify_event_chain()} (TC-13, TC-14).
\item \textbf{NFR-S-07} No CNIC stored. \textit{Met}: no such column; checked by the privacy suite.
\end{itemize}

\subsection{Privacy, maintainability and decision quality}\label{sec:privacy-maintainability-decision-quality}
\begin{itemize}
\item \textbf{NFR-PR-01} Exact location never appears in profiles, listings, API responses or logs. \textit{Met} for the built API: every response model and log line is scanned (suite 14).
\item \textbf{NFR-D-01} 100\% of stored assessments record \code{config_version}. \textit{Met} (TC-71; the column is NOT NULL).
\item \textbf{NFR-D-04} Automated tests run on every build and a failing test blocks merge. \textit{Met}: three CI jobs on every pull request.
\item \textbf{NFR-Q-01} At mid-term, $\geq$7 of 13 scenarios correct in state and explanation. \textit{Met}: 7 of 7 (Section~\ref{sec:scenario-results-nfr-q-01}).
\end{itemize}
