\section{Repository Hygiene and Version Control}
The team maintains professional Git repository standards on GitHub (\url{https://github.com/Areeba444/DigitalMohalla}):
\begin{itemize}
    \item \textbf{Branching Strategy:} Trunk-based development using protected \texttt{main} and \texttt{develop} branches. All functional changes are developed on dedicated feature branches (e.g., \texttt{feature/beta-posterior}, \texttt{feature/trust-edges}, \texttt{feature/lender-evidence-screen}).
    \item \textbf{Pull Request Protocol:} Direct pushes to protected branches are disabled. Every pull request requires green CI checks and peer review from another team member before merging.
    \item \textbf{Atomic Commits:} Commits are granular, accompanied by imperative semantic commit messages, and pair implementation code with corresponding automated unit and integration tests.
\end{itemize}

\section{Continuous Integration (CI) Pipeline}
The repository integrates automated CI via GitHub Actions (\texttt{.github/workflows/ci.yml}):
\begin{enumerate}
    \item \textbf{Backend Pipeline:}
    \begin{itemize}
        \item Code quality: Linting and formatting enforcement via \texttt{ruff check} and \texttt{ruff format}.
        \item Static type analysis: Strict type checking of domain logic via \texttt{mypy}.
        \item Security audits: Automated vulnerability and secret scanning via \texttt{bandit} and \texttt{pip-audit}.
        \item Automated test execution: Comprehensive test execution against a live PostgreSQL 16 service container.
    \end{itemize}
    \item \textbf{Frontend Pipeline:}
    \begin{itemize}
        \item Clean dependency installation via \texttt{npm ci}.
        \item Static type validation using \texttt{tsc --noEmit}.
        \item Linting via ESLint (flat config) and automated component testing via \texttt{jest}.
        \item Security auditing via \texttt{npm audit}.
    \end{itemize}
    \item \textbf{Contract Drift Guard:} Automated export of \texttt{openapi.json} and verification that the generated TypeScript client has no uncommitted diffs.
\end{enumerate}

\section{Continuous Deployment (CD) Architecture and Live Status}
The deployment infrastructure utilizes a containerized cloud deployment model:
\begin{itemize}
    \item \textbf{API Service Container:} Packaged via multi-stage \texttt{Dockerfile} using Python 3.12, running under a non-root security context. Applies Alembic database migrations automatically at container startup before launching Uvicorn.
    \item \textbf{Cloud Hosting Environment:} Hosted on Render (Singapore region) backed by a managed cloud PostgreSQL 16 database on Neon.
    \item \textbf{Live Deployed Endpoints:}
    \begin{itemize}
        \item Web Application: \url{https://digitalmohalla-web.onrender.com}
        \item Backend API Health Gate: \url{https://digitalmohalla-api.onrender.com/health}
    \end{itemize}
    \item \textbf{Rehearsal \& Rollback Verification:} Smoke test verification (TC-90--92), automated zero-downtime health gates (\texttt{/health}), containerized restart validation, and documented rollback rehearsal procedures on Render/Neon infrastructure.
\end{itemize}
