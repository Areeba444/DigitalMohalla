## Assessment output object (`AssessmentResult`)

Returned by `assess(request)` (Student 2's `AssuranceResult`, Algorithm doc §2) and stored as one `assessment` row: `assurance_state`, `policy_decision`, `rule_fired`, `hold_reason`, `posterior_mean`, `ci90_low`, `ci90_high`, `effective_evidence`, `direct_evidence`, `indirect_evidence`, `manipulation_risk`, `manipulation_level`, `manipulation_corroborated`, `manipulation_signals`, `safeguards`, `explanation`, `config_version`. The field-by-field mapping between the engine contract and these columns is in `Assurance_Data_Dictionary.md` §5. The lifecycle holds the request exactly when `hold_reason` is set (rules R2, R4); on timeout or failure there is no object and the request is held with reason `engine_failure` (FR-T-07).
