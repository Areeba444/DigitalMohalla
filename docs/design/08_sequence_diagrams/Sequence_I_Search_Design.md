## 1. What the diagram shows and why

1. **Retrieval with eligibility inside the query.** The member's community, PUBLISHED status, "not their own item", "owner has not blocked them" and the date filter all sit in the same SELECT as the keyword and vector match. A few hundred items need no vector index, so exact search can filter first. Fetching the top 100 and filtering afterwards (issue I-5) could return few or no results.
2. **Two fallbacks, each in its own `alt`.**
   - If the embedding model fails, times out or does not fit the host's memory, the same query runs on full-text rank only, and the response says "keyword results only" (FR-S-02, NFR-R-04).
   - If the engine is unavailable, every lender gets the same default prior, so no lender moves up or down for a reason that has nothing to do with them.
3. **Ranking uses evidence, never a single trust number.** The ranker reads each lender's factors with their confidence. A lender with no history is treated as the prior (FR-S-04, "not enough history yet"), which matches "zero history is not a negative finding". The weights are DA-22's; this diagram fixes only the inputs.
4. **Logging is Student 3's part (FR-S-05), separated from ranking.**
   - Logged: query, filters, mode and the shown ranks, then each click.
   - Ignored impressions are derived later as shown minus clicked, which saves one write per result.
   - Nothing about location is sent or logged.
   - Student 3 evaluates search that Students 1 and 2 build (DA-25), so the scorer is not the author.
